The one rule it is built around: answer only from legal documents it has actually found, and say so plainly when it finds nothing.

Why this problem

Most people never get help with everyday legal trouble: a deposit that isn't returned, a refund that never comes, salary that stops. They don't know which law applies, and a lawyer feels expensive. AI can close that gap only if people can trust it, and the biggest failure of AI legal tools is inventing laws and cases with total confidence. So trust comes first: every answer must point to sources the system actually retrieved.

Assumptions

  • People ask about Indian law, in text. Questions about another country's law get a polite decline, not a guess.
  • They want to understand where they stand and what to do next. Nyaya explains; it doesn't replace a lawyer, and every answer says so.

How it works

Intent gateGreeting, non-Indian law, or a real legal question?
›
RewriteTurns follow-ups into a standalone search using the chat so far
›
Hybrid searchLegal library (FAISS) and live web (Tavily) in parallel
›
AnswerCitizen: plain answer. Lawyer: draft and critique loop
›
ShowAnswer with its sources and a quality score

Two modes. Citizen gives plain-language guidance on rights and procedures. Lawyer runs five agents in a loop (issue extractor, planner, retriever, drafter, critic) until the critic scores the draft 0.7 or higher, or three rounds pass.

The legal library has 39 Indian legal documents (recent acts, judgments, and question-and-answer sets on the IPC, CrPC and Constitution), split into 4,209 searchable chunks. The web search blocks social-media and user-generated sites as sources.

Built with FastAPI, LangGraph (13 steps across the two agents), Groq running Llama 3.1 8B, FAISS with all-MiniLM-L6-v2 embeddings, Tavily, SQLite chat history, and a React frontend with Clerk sign-in. A Streamlit version runs without the frontend.

How it avoids made-up laws

A measured relevance cutoff

Search returns 8 candidates and keeps only those within a distance of 1.25. I measured it: real legal questions scored 0.70 to 1.15, off-topic ones 1.31 to 1.76. Weak matches are dropped, not used as filler.

Self-critique

In lawyer mode a separate critic agent reviews every draft and sends weak ones back before the user sees them.

Honest failure

If the library and the web both come back empty, it never asks the model to answer anyway. It says it couldn't find reliable information.

Clear labels

The score is called a quality score, not an accuracy score. Every answer says it isn't legal advice and that cited acts and judgments should be checked.

Grounded writing

The model is told never to invent or guess a case, citation, section or article, and to say so when its sources lack one.

Sources on show

Every answer lists where it came from, so a user or a lawyer can check it in seconds.

The test script saves every raw answer and flags any case name missing from its listed sources, the first sign of an invented citation.

Each run writes the answers and these checks to outputs/, so the same 12 cases can be re-run after every change, or against a stronger model, and compared side by side.

Where it fails

  • No hard check on citations yet. The no-invention rule is an instruction backed by retrieval. Nothing in code compares each cited section against the retrieved text. That is the first thing I would add.
  • The library is narrow. It leans toward recent acts and judgments, so everyday tenancy, consumer and wage questions rely mostly on web search, which is less trustworthy.
  • Text and English only, no voice or drafted notices yet, and the quality judge isn't checked against human grades.

Scale and cost

Each question costs a few calls to Groq's low-cost Llama 3.1 8B plus one web search, the main cost once Tavily's free tier runs out. Greetings skip research, cutting the cost of non-legal messages by about 97%. A larger model is one setting away (GROQ_MODEL); new laws mean adding documents and rebuilding the index. A lawyer reviews the library and a monthly sample of answers.
